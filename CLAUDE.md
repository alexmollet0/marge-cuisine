# Chefup — contexte du projet

App SaaS de calcul de marges pour restaurateurs, nom commercial **Chefup** (ne jamais
traduire ce nom, dans aucune langue). React + Vite, déployée sur Vercel, code sur GitHub
(dépôt encore nommé `marge-cuisine` — voir note de renommage ci-dessous), branche `main`.

## Fichiers clés
- `src/App.jsx` — toute l'application (un seul gros fichier), y compris le composant `Logo`
- `api/scan-invoice.js` — fonction serveur Vercel qui appelle l'IA (Claude Haiku) pour lire les factures scannées
- `src/storage.js` — stockage local (localStorage), préfixe de clé `"chefup:"` (migré depuis `"marge-cuisine:"` le 2026-07-31, avec copie automatique des données existantes)

## Déploiement
Vercel redéploie automatiquement à chaque push sur `main`. Variable d'environnement
`ANTHROPIC_API_KEY` déjà configurée sur Vercel (ne pas y toucher).

## Fonctionnalités déjà en place
- Calcul de marge par recette (coût ingrédients vs prix de vente, TVA configurable)
- Garde-manger avec fournisseurs, historique de prix, catégories

- Assistant d'ajout/modification d'ingrédient en 2-3 étapes : recherche unique (catalogue + ingrédients existants, pas de liste par défaut), prix+unité fusionnés en une étape, catégorie (uniquement pour une création), bouton "Modifier" sur chaque ligne du garde-manger qui pré-remplit l'assistant pour mettre à jour un prix existant sans dupliquer
- Impression : ticket recette avec/sans prix (fiche technique), fiche allergènes de toutes les recettes
- Bilingue FR/ES

- Scanner de factures, calculateur de prix au kg/L pour les produits vendus à la pièce/au sachet (2026-07-30) : cas réel remonté par l'utilisateur — une ligne du type "3 PCE x 28.90€" (ex: Saint-Jacques surgelées, bidon d'huile, beurre en paquet) n'indique pas le poids/volume d'une pièce, donc l'app ne peut pas calculer de prix au kg/L et forçait un prix à 0€ avec juste un avertissement texte, obligeant l'utilisateur à faire le calcul mental lui-même. Le résultat pousse automatiquement `item.unit`/`item.unitPriceHT`, donc plus besoin de taper le prix final à la main.

  2. **OCR indépendant (`tesseract.js`) sur les photos.** Nouvelle fonction `runOcr` (`src/App.jsx`) : fait lire la photo par un moteur OCR classique (pas une IA), en plus de l'IA de vision, avec les 3 langues de l'app chargées ensemble (`fra+spa+eng`). La transcription obtenue est envoyée à Claude comme indice supplémentaire (jamais comme vérité absolue : le prompt lui dit explicitement que l'image reste la référence en cas de désaccord) — l'idée est qu'un moteur OCR classique et une IA de vision se trompent rarement sur le même chiffre de la même façon, donc les recouper aide l'IA à se corriger elle-même. Best-effort et jamais bloquant : si l'OCR échoue, le scan continue normalement sans lui (`runOcr` avale ses propres erreurs et renvoie une chaîne vide).
  3. **Côté serveur (`api/scan-invoice.js`)** : accepte maintenant soit `{ image, mediaType, ocrText }` (photo, avec transcription OCR optionnelle ajoutée comme bloc de texte supplémentaire dans le message envoyé à Claude), soit `{ text }` (texte PDF natif, aucune image envoyée). Le prompt a été légèrement généralisé en tête ("Analyse le document fourni...") pour rester cohérent quelle que soit la modalité, le reste des règles ne change pas.
  Les deux librairies (`pdfjs-dist`, `tesseract.js`) sont chargées en **import dynamique** (`await import(...)`) dans les fonctions qui en ont besoin, pas en import statique en tête de fichier — ce sont de grosses dépendances qui ne doivent peser sur le chargement de l'app que pour les utilisateurs qui scannent effectivement.
  **Risque assumé consciemment avec l'utilisateur avant de coder** : ce changement ajoute 2 nouvelles dépendances npm et n'a pu être vérifié par aucun test local (Node.js indisponible), en particulier l'intégration de `pdfjs-dist` avec Vite (référence au worker via `new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)`, réputée délicate même pour des devs qui peuvent tester). Le risque réel expliqué à l'utilisateur : si l'intégration est mal configurée, le déploiement Vercel échoue proprement (la version précédente qui marchait reste en ligne, rien ne casse pour les utilisateurs) — mais je n'ai aucun accès au tableau de bord Vercel pour vérifier moi-même. **À faire après ce push : l'utilisateur doit vérifier que le déploiement Vercel a bien réussi (pastille verte), et coller le message d'erreur ici si jamais c'est rouge.**
