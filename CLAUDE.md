# Chefup — contexte du projet

App SaaS de calcul de marges pour restaurateurs, nom commercial **Chefup** (ne jamais
traduire ce nom, dans aucune langue). React + Vite, déployée sur Vercel, code sur GitHub
(dépôt encore nommé `marge-cuisine` — voir note de renommage ci-dessous), branche `main`.

## Fichiers clés
- `src/App.jsx` — toute l'application (un seul gros fichier), y compris le composant `Logo` (exporté) et les constantes de marque `BRAND_SOLID`/`BRAND_GRADIENT`/`BRAND_SHADOW` (exportées)
- `src/Landing.jsx` — page d'accueil publique (hero, points forts, pricing 39€/mois), affichée par `AuthGate` (`src/Auth.jsx`) avant le formulaire de connexion tant qu'aucune session n'existe. Purement présentationnelle, aucune donnée. Boutons → basculent `AuthGate` sur signup/login (`showLanding` state dans `Auth.jsx`).
- `api/scan-invoice.js` — fonction serveur Vercel qui appelle l'IA (Claude Haiku) pour lire les factures scannées
- `api/scan-recipe.js` — fonction serveur Vercel séparée qui appelle l'IA pour lire une fiche technique/recette existante scannée (photo/PDF) et pré-remplir une recette. Volontairement isolée de `api/scan-invoice.js` (autre prompt, autre besoin), pour ne jamais risquer de régresser le scanner de factures.
- `api/send-reminders.js` — fonction serveur Vercel déclenchée par un cron Vercel quotidien (`vercel.json`) : alertes email (inactivité, marge sous objectif, fin d'essai sans abonnement). Protégée par `CRON_SECRET`.
- `src/storage.js` — **stockage par compte (Supabase, depuis 2026-08-02)**, plus du localStorage. Même interface `get/set/delete/list` qu'avant (aucun autre fichier n'a eu besoin de changer), mais lit/écrit maintenant dans la table Postgres `kv_store` du projet Supabase, filtrée par compte via Row Level Security.
- `src/supabaseClient.js` — client Supabase partagé (`createClient`), utilise `import.meta.env.VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`
- `src/Auth.jsx` — porte d'authentification (`AuthGate`) : affiche un formulaire connexion/inscription tant qu'aucune session Supabase n'existe, sinon affiche l'app. Branché dans `src/main.jsx` autour de `<App/>`. Connexion obligatoire, pas de mode démo sans compte.
- `src/Billing.jsx` — porte d'abonnement (`SubscriptionGate`), imbriquée DANS `AuthGate` (`src/main.jsx` : `AuthGate > SubscriptionGate > App`). Voir section Stripe ci-dessous.
- `api/_lib.js` — utilitaires serveur partagés par les fonctions Stripe (client Stripe, client Supabase admin service_role, vérification du token utilisateur). Préfixé `_` pour que Vercel ne le déploie pas comme route.
- `api/create-checkout-session.js`, `api/create-portal-session.js`, `api/stripe-webhook.js` — fonctions serveur Stripe (voir section Stripe ci-dessous).

## Déploiement
Vercel redéploie automatiquement à chaque push sur `main`. Variables d'environnement configurées sur Vercel (ne pas y toucher) :
- `ANTHROPIC_API_KEY` (scan de factures)
- `VITE_SUPABASE_URL` et `VITE_SUPABASE_ANON_KEY` (authentification + stockage des données, ajoutées le 2026-08-02) — la clé "anon" est une clé publique par conception (comme une clé Stripe "publishable"), sans danger dans le bundle frontend ; la vraie protection vient de la policy RLS sur la table `kv_store` côté Supabase.
- **À ajouter pour Stripe (2026-08-03, voir section EN COURS)** : `STRIPE_SECRET_KEY`, `STRIPE_PRICE_ID`, `STRIPE_WEBHOOK_SECRET` (secrètes, jamais préfixées `VITE_`), `SUPABASE_SERVICE_ROLE_KEY` (clé admin Supabase qui contourne RLS — jamais dans le bundle frontend, utilisée uniquement par `api/_lib.js`).
- **À ajouter pour les alertes email (2026-08-04, voir section EN COURS)** : `RESEND_API_KEY` (clé API Resend, distincte des identifiants SMTP déjà configurés côté Supabase) et `CRON_SECRET` (protège `api/send-reminders.js` contre un déclenchement par n'importe qui).

**Nom de domaine (2026-08-02)** : `getchefup.com` acheté directement via Vercel (Settings → Domains) et connecté automatiquement — `chefup.com` était déjà pris. C'est maintenant l'adresse de référence de l'app (Site URL Supabase pointe dessus). L'ancienne adresse `marge-cuisine.vercel.app` reste fonctionnelle en parallèle (toujours dans les Redirect URLs Supabase), mais `getchefup.com` est l'adresse à utiliser/donner aux utilisateurs. Le nom du dépôt GitHub et du projet Vercel restent `marge-cuisine` (voir note de renommage plus bas, inchangée).

**Envoi d'email (2026-08-02)** : Supabase utilise désormais un SMTP personnalisé via **Resend** (domaine `getchefup.com` vérifié) au lieu du service email par défaut de Supabase — nécessaire pour personnaliser le contenu des emails (le service par défaut ne permet pas d'éditer les templates). Réglages SMTP dans Supabase (Authentication → Emails → SMTP Settings) : host `smtp.resend.com`, port `587` (le port `465` a été essayé en premier et ne fonctionnait pas de façon fiable), username `resend` (littéralement ce mot, pas un nom de projet), password = clé API Resend, sender `hello@getchefup.com`. Templates "Confirm signup" et "Reset Password" personnalisés aux couleurs Chefup (HTML avec styles inline, compatible clients email).

- Campagne de test du scanner sur 15 fausses factures FR/ES reproduites (2026-07-31), à la demande de l'utilisateur : 15 factures HTML imitant des fournisseurs réels (Métro, Promocash, Transgourmet, Makro España, Mercadona...) converties en images (Edge en mode headless, sans Node.js) et envoyées une à une à `/api/scan-invoice` en production (marge-cuisine.vercel.app). Précision mesurée avant correction : 83/100 lignes correctes. Bugs confirmés et corrigés :
  1. **`weighable` peu fiable pour les produits en sachet/boîte/plaquette** (Saint-Jacques surgelées, beurre en plaquette, concentré de tomate en boîte) : l'IA les classait à tort `weighable: false`, ce qui empêchait le calculateur de prix de se déclencher et laissait passer un prix silencieusement faux. Correction de fond côté code : `pricingUnknown` (`computeItemPricing`, `src/App.jsx`) ne dépend plus du tout de `weighable` — un contenu manquant déclenche toujours le calculateur, quel que soit le type de produit.
  2. **Calcul multipack "NxVOLUME" non fiable** (ex: "Carton 6x75cl" → l'IA a renvoyé 6 ou 0.75 au lieu de 4.5 dans plusieurs tests, soit un prix faux jusqu'à x6). Prompt renforcé avec un calcul explicite en 2 étapes. Filet de sécurité déterministe ajouté côté code : nouvelle fonction `extractDeterministicContent` (`src/App.jsx`, à côté de `computeItemPricing`) qui recalcule elle-même le contenu via une expression régulière sur `rawLabel` dès que le motif "NxVOLUME" est reconnaissable, et écrase la valeur de l'IA (plus fiable qu'elle sur ce point précis d'après les tests).
  3. **Conversion grammes→kg parfois oubliée** (ex: "Bloc 500g" → l'IA a renvoyé packageContent 500 avec l'unité "kg" au lieu de 0.5, soit un prix faux x1000). Même filet `extractDeterministicContent` : détecte un poids en grammes dans le texte brut et le convertit lui-même en kg.
  4. **Lignes de remise/récapitulatif pas toujours exclues** : l'IA laissait parfois passer une ligne "REMISE -5%" dans `items` avec tous les champs à `null` au lieu de l'omettre complètement (contrairement à la consigne du prompt), créant une carte vide et confuse à vérifier manuellement. Prompt renforcé + **filet de sécurité côté code** (`handleScanFile`, `src/App.jsx`) : toute ligne renvoyée par l'IA sans nom exploitable est désormais silencieusement ignorée avant traitement, quel que soit le type de facture.
